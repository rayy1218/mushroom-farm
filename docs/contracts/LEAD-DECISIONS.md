# Lead decisions (binding for every contract; frozen 2026-10-08)

| # | Topic | Decision |
|---|---|---|
| 1 | Reading field names | One set everywhere: `room_id`, `t`, `T`, `RH`, `CO2`, `t_out`, `rh_out`, `ac_mode`, `ac_setpoint`, `fog`, `fan`, `lights`, `circ`, `power_w`, `kwh` (C1 column names; `T`/`RH`/`CO2` match controller.js and sim.js). db.js takes and returns these keys; C2 builds rows with these keys; C3 sends them unchanged; C5 reads them. No renaming layer in any contract. Bucket averaging returns the same keys (no `n`). |
| 2 | The `room` event | C2 (room manager) owns every `room` event: lifecycle (create, update, archive, restart, crash) AND live summary changes (end of a tick when stage/crop/alarms/running/error change, after applySettings, after ackAlarm). C3 only relays C2 events to the stream; it derives nothing. |
| 3 | Fake db errors | The fake db sets `code: 'ERR_SQLITE_ERROR'` and `errcode` exactly as node:sqlite would (275 CHECK, 1299 NOT NULL, 787 FOREIGN KEY, 3091 wrong type, 2067 UNIQUE), so C3's `(err.errcode & 0xff) !== 19` fatal rule behaves the same against the fake and the real db. A shared test runs against both. |
| 4 | Live-feed watchdog | Defined in C5 (web/api.js `stream(onEvent)`): if no event and no `: ping` comment arrives for 45 s (the server pings every 15 s), the client closes and reconnects; after any reconnect the page reloads the last minutes from GET /readings (C3). C3 refers to C5 for this. |
| 5 | Restart route | web/api.js (C5) has `restartRoom(id)` for C3's POST /api/rooms/:id/restart; the Rooms UI shows a Restart button on a stopped room. |
| 6 | Untrusted settings | Settings from HTTP (and from any import) are NEVER passed to ClimateController.applySettings directly. They go through ClimateController.importSettings (which builds from defaultSettings and copies only known keys), and only its `settings` result is applied (into the running cfg with applySettings, which is then safe) and stored. The fakes do the same. |
| 7 | Fakes and shared constants | The lead writes every fake in wave 0: tests/fakes/db.js, tests/fakes/rooms.js, tests/fakes/api-server.js. Shared constants and error classes live in small files the lead also writes in wave 0: server/db-common.js (NotFoundError, …) and server/rooms-common.js (RoomError, DEMO_ROOM, …). server/db.js and server/rooms.js import from them; fakes import only from these common files, never from server/db.js or server/rooms.js. |
| 8 | Wave plan | The API stream's wave 1 `server/main.js` holds the real `openDb` and `createRoomManager` wiring (tested with stubs, C3 section 12.1). After the wave 1 merge the lead runs the wave 1.5 gate (C3 section 12.2). The wave 2 streams branch from `master` only after the gate passes and run their headless Chrome checks against the real server (C5 section 7.10). Wave 3 re-runs every test and check on the final merge and adds `tests/api-real.test.js` (C3 section 12.2). Spec section 6 amended to match. |
| 9 | Reading columns (amends 1) | SQLite column names ignore case, so a `T` column cannot sit beside the time column `t`. The temperature column is `temp`; db.js alone renames it to `T` on the way in and out. Every key any module sees is the decision 1 set; no other module renames anything. |
| 10 | Stream close event (amends C3 10.1) | A live-feed connection is removed on the response's `close` event (`res.on('close')`), not the request's. On Node 22.20, once the request body has been read `req.closed` is already true and a `req` `close` listener added then never fires, so aborted streams would never be removed. Found by the wave 0 review of the fake API server. |
| 11 | Wave 0 commit rules (waiver) | Tasks 4 to 7 of wave 0 stay in one commit (a4a8504) and the review-fix commits keep their `fix(...)`/`test(...)` prefixes. History is not rewritten; the per-task commit rule still applies to later streams. |
| 12 | Spawn scoring (C7 8.2) | In the spawn run, air below the temperature band counts as in band while the controller's `coreControl` rule cools for the block core (`core − coreTarget > T − spT`). The bags are sealed and the core is what matters; without this rule spawn always fails on air temperature (0.2 % in band at 2000 blocks, 99.8 % excused, core at most 28.2 °C). |
| 13 | Cycle stream commits (waiver) | stream/cycle keeps task 1 without its test in the same commit and tasks 2 to 16 in one commit (f79c779). History is not rewritten. |
| 55 | Air exchange (C9; 14–54 are reserved by the parked wave 2 decisions on `wave2/contracts-folded`) | The one fresh-air fan, its levels, `env.vent`, `rules.airMode`, `baseFan`, `fanLevel`, `rhAction`, `fogBoost` and the AC-during-purge rules are replaced by an on/off intake + exhaust pair (`air.on`) with short purges capped at `rules.purgeMaxS`, no Prepare step (dropped after a prototype, spec 2.3), and the `airTooSmall` alarm. Contract C9 (`docs/contracts/air.md`) overrides the sections listed in its section 10. The reading key `fan` becomes `air`; database upgrade 2 is C9's, so wave 2's planned upgrade becomes 3. `SETTINGS_VERSION` 2 with `upgradeSettings` for older settings and stored room settings. |
