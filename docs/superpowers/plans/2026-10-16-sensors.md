# Sensors, detail page, device app (v2 iteration 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Three streams (D, S, W) run in parallel in separate worktrees; each owns disjoint files. Steps use checkbox (`- [ ]`) syntax. Use superpowers:test-driven-development inside each task.

**Goal:** The farm app polls T/RH and CO₂ sensors over Modbus TCP, shows each room's sensor status and last 50 readings on a room detail page inside the previous app's layout; a separate device app plays the gateway and its sensors.

**Architecture:** Three independent units joined only by wire formats: the device app (Modbus TCP server + control page) ⇄ Modbus TCP ⇄ the farm server (Modbus client, poller, SQLite, JSON API) ⇄ HTTP JSON ⇄ the farm web page. Each stream builds one unit against the frozen interfaces below.

**Tech Stack:** Node 22.13+ ES modules, `node:net`, `node:http`, `node:sqlite`, `node:test`; plain HTML/CSS/JS, no build, no npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-sensors-design.md` (sections cited as §n). Iteration 1 spec: `docs/superpowers/specs/2026-10-16-rooms-design.md`.

**Deviation from the usual plan format (owner asked for maximum speed):** code is not pre-written in this plan. Implementers are Sonnet and write code test-first against the frozen interfaces and the test lists below. Opus reviews and a browser check follow the merge.

## Frozen interfaces

### I1. Modbus TCP wire format (D and S)

As spec §3. Summary:

| Item | Value |
|---|---|
| MBAP | `tid u16, pid u16 = 0, len u16 = 1 + PDU length, unit u8` (big-endian) |
| Request PDU | `fn u8 (3 or 4), start u16, qty u16` → total frame 12 bytes |
| Reply PDU | `fn u8, byteCount u8 (= 2·qty), regs u16 × qty` |
| Exception PDU | `fn + 0x80 u8, code u8` |
| T/RH probe | fn 4, start 1, qty 2 → `[round(T·10) as int16 two's complement, round(RH·10)]` |
| CO₂ sensor | fn 3, start 0, qty 1 → `[round(ppm)]` |

### I2. Device app module (D; used by the lead's e2e test)

```js
// device/server.js
export async function startDevice({ modbusPort = 1502, httpPort = 8090, statePath, host = '127.0.0.1' } = {})
// → { modbusPort, httpPort, sensors, close: async () => void }   (ports are the real bound ports, so 0 works)
// `sensors` is the in-memory store (device/sensors.js) so tests can change values/answering directly:
//   sensors.list() → [{ address, kind: 'trh'|'co2', t, rh, co2, answering }]
//   sensors.add({ address, kind }) / sensors.update(address, patch) / sensors.remove(address)
// statePath undefined → no file (memory only); device/main.js passes DEVICE_STATE or device/state.json
```

`device/main.js` reads `DEVICE_MODBUS_PORT` (1502), `DEVICE_HTTP_PORT` (8090), `DEVICE_STATE` (`device/state.json` next to main.js), prints `Device app: Modbus on :<p>, control page http://localhost:<h>`, stops cleanly on SIGINT/SIGTERM.

### I3. Farm HTTP API additions (S serves, W consumes)

Room object (all room responses):

```json
{ "id": 1, "name": "Room 1", "length": 6, "width": 4, "height": 2.5, "volume": 60,
  "trhAddress": 1, "co2Address": null, "createdAt": 0, "updatedAt": 0 }
```

| Route | Response |
|---|---|
| `GET /api/rooms/:id` | 200 room · 404 `{error:'Room not found'}` |
| `GET /api/rooms/:id/sensors` | 200 `[trhSensor, co2Sensor]` · 404 `{error:'Room not found'}` |
| `POST /api/rooms`, `PUT /api/rooms/:id` | body may include `trhAddress`, `co2Address` (int 1–247 or null; missing = null); errors per spec §4 with `field` `trhAddress` / `co2Address` |

Sensor object:

```json
{ "kind": "trh", "address": 1, "status": "online", "failuresInRow": 0,
  "lastOk": { "at": 1760600000000, "t": 25.3, "rh": 88.1 },
  "readings": [ { "at": 1760599995000, "ok": true, "t": 25.2, "rh": 88.0 },
                { "at": 1760600000000, "ok": false, "t": null, "rh": null } ] }
{ "kind": "co2", "address": null, "status": "not-wired", "failuresInRow": 0, "lastOk": null, "readings": [] }
```

`status` ∈ `not-wired | no-data | online | timeout | offline` (§6). CO₂ objects use `co2` instead of `t`/`rh`. `readings` oldest → newest, at most 50, only for the current address.
