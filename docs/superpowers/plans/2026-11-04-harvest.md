# Harvest and yield Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harvests recorded per room, run, crop and flush (from the harvest check's Done or Record a harvest), with kg per block, biological efficiency, RM value and cost per kg on a Harvest room tab, a farm Harvest page, an Overview card, a CSV and a printable myGAP 4-6 sheet.

**Architecture:** Two new tables (`runs`, `harvests`, database version 20). The crop API opens and ends runs with the program in one transaction. `server/harvests.js` records, edits and deletes harvests (the harvest check's Done writes its rows inside the task's close transaction) and builds the views; the figures are pure in `server/harvest-math.js`. Routes in `server/harvest-api.js`. The pages: `web/harvest-card.js` (room tab), `web/harvest-page.js` (farm page and the myGAP sheet), pure parts in `web/harvest-math.js`.

**Tech Stack:** Node 22 (`node:http`, `node:sqlite`, `node --test`), plain JS modules, no build step, no dependencies.

Spec: `docs/superpowers/specs/2026-11-04-harvest-design.md` (read it first; section numbers below are its). Branch `feat/harvest`, worktree `.claude/worktrees/harvest`. Run all tests with `npm test` (2010 pass at the start). Commit as the repo's configured user (Ray Tham); never push.

Conventions of this repo (follow them): comments in short plain sentences saying what and why, as the neighbouring code; tables in specs; metric units; one formatter per quantity; every SQL table STRICT; tests with `node:test` and `assert/strict`; pages are plain DOM modules with a `mount(container, opts)` returning `{ destroy() }` or a `createXCard(host, opts)` returning `{ destroy() }`; colour only for state (DESIGN.md).

`VERSION = 20`. The tables:

```js
// Runs of blocks and their harvests (spec 2026-11-04-harvest-design.md 2): a run opens when a room gets its crops or new
// blocks and ends at the next new blocks or when the crops are cleared; a harvest belongs to the run it was picked in.
const RUNS_HARVESTS = `
CREATE TABLE IF NOT EXISTS runs (
  id         INTEGER PRIMARY KEY,
  room_id    INTEGER NOT NULL,
  started_at INTEGER NOT NULL,
  ended_at   INTEGER,
  crops      TEXT    NOT NULL,
  partial    INTEGER NOT NULL DEFAULT 0 CHECK (partial IN (0, 1))
) STRICT;
CREATE UNIQUE INDEX IF NOT EXISTS runs_open ON runs (room_id) WHERE ended_at IS NULL;
CREATE INDEX IF NOT EXISTS runs_by_room ON runs (room_id, started_at);
CREATE TABLE IF NOT EXISTS harvests (
  id         INTEGER PRIMARY KEY,
  room_id    INTEGER NOT NULL,
  run_id     INTEGER NOT NULL,
  crop       TEXT    NOT NULL,
  stage      TEXT    NOT NULL,
  flush      INTEGER,
  blocks     INTEGER NOT NULL,
  kg         REAL    NOT NULL CHECK (kg > 0 AND kg <= 10000),
  picked_at  INTEGER NOT NULL,
  worker     TEXT,
  task_id    INTEGER,
  created_at INTEGER NOT NULL
) STRICT;
CREATE INDEX IF NOT EXISTS harvests_by_run ON harvests (run_id, picked_at);
CREATE INDEX IF NOT EXISTS harvests_by_time ON harvests (picked_at);
CREATE INDEX IF NOT EXISTS harvests_by_task ON harvests (task_id) WHERE task_id IS NOT NULL;`;
```

In `migrate`: `if (version < 20) { db.exec(RUNS_HARVESTS); upgradeHarvests(db, Date.now()); }` where `upgradeHarvests` (a module function above `migrate`) does section 2.2: for each room in `room_crops` (grouped by room, by `position`), find its done rows `WHERE rule_key IN ('harvestAm','harvestPm','harvestDaily','reishiRim') AND status = 'done' AND amount > 0` ordered by `closed_at`; insert the run with `started_at = MIN(now, first closed_at)`, `partial = 1`, `crops` JSON; insert each row as a harvest of the first room crop whose family the rule is for (import `FAMILY_OF` and `DAILY_RULES` from `./task-rules.js`: the rule's `families`), `blocks` that crop's, `stage` the program's (`room_programs.stage`, 'fruiting' without a row), `flush` null, `picked_at` and `created_at` the row's `closed_at`, its `worker`, `task_id` the row id. Rooms without crops: nothing.

The row shapes:

Methods (prepared statements in `q`):

| Method | Does |
|---|---|
| `openRun(roomId)` | The open run or null |
| `getRunById(id)` | A run or null |
| `cropRuns(roomId)` | Every run, newest `started_at` first (then id desc) (`listRuns` is the simulation runs') |
| `runsBetween(from, to)` | Runs of any room overlapping [from, to] (`started_at <= to AND (ended_at IS NULL OR ended_at >= from)`) |
| `insertHarvest(fields)` | → the row (`fields`: `{ roomId, runId, crop, stage, flush, blocks, kg, pickedAt, worker, taskId, at }`) |
| `getHarvest(id)`, `runHarvests(runId)` (oldest first), `taskHarvests(taskId)`, `harvestsBetween(from, to)` (picked_at in [from, to], oldest first) | Reads |
| `updateHarvest(id, { kg, pickedAt })` | Updates the row; when it came from a check, sets that task's `amount` to `ROUND(SUM(kg), 3)` of the task's harvests in the same transaction. → the row or null |
| `deleteHarvest(id)` | Deletes; the same task update (null when none of the task's harvests are left). → true when a row went |
| `setProgram(roomId, p, run = null)` | As now, plus inside its transaction: `run.change` `'start'` (insert a run at `run.at` with `p.crops`), `'update'` (set the open run's crops; throw `Error('No open run')` when none), `'end'` (set the open run's `ended_at`), `'restart'` (end then start) |
| `closeTask(id, fields, next = null, harvests = [])` | As now, plus inserting each harvest inside the transaction when the row closed |
| `deleteRoom` | Also `DELETE FROM harvests WHERE room_id = ?` and `DELETE FROM runs WHERE room_id = ?` |
